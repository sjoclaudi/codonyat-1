# Changelog

All notable changes to codonyat are documented in this file.

## [1.3.1] - 2026-10-16

Research use only. No clinical or resistance claims.

### Changed
- **`--collapsed-read-counts`**: a read name ending in `_<digits>` is treated as a
  collapsed duplicate count only when this flag is set. By default each SAM row
  counts once (`sample_123` is one observation). HIV regression fixtures do not
  use a numeric multiplicity suffix, so they stay byte-identical without the flag.
- Multi-interval proteins carry the reading frame across parts. A codon that
  crosses a junction is kept, and `SamEntry.codon_at` / `FullReference.get_seq_at`
  build it from the actual part coordinates (for example positions 10, 11 and 12
  of intervals 1-10;11-30).
- `--protein` names are matched exactly against parsed FASTA header annotation
  names, not as substrings of the header line (`--protein S` no longer matches
  `NS(...)`).

### Unchanged
- SARS-CoV-2 ORF1ab (`266-13468;13468-21555`) still has 7097 codons.
- No Nextflow content in this repository.

## [1.3.0] - 2026-10-16

Research use only. All 1.3.0 features are **opt-in**. Default TSV and XML remain
byte-identical to 1.2.1 (and therefore to 1.1.0 on single-record HIV-1).

### Added
- **`--min-baseq`**: if set, count a codon only when all three bases pass that
  Phred-like quality. Off by default.
- **`--stats PATH`**: sidecar TSV with per-variant Wilson 95% CI, two-sided
  Fisher's exact strand-bias p-value, and flags `lowfreq`, `sb`, `lowcov`; plus
  per-codon and per-gene Shannon (raw and normalised), Gini–Simpson, nucleotide π
  and amino-acid π. Codons containing N or gaps are excluded from diversity.
- **`--aavf PATH`**: AAVF v1.0 writer (`##fileformat=AAVFv1.0`). FILTER uses the
  stats flags. CAT and SRVL are never emitted. Partial/gapped codons map to `X`;
  amino-acid indels are not called. Header source is
  `codonyat-1.3.0 (research use only)`. `##reference` is the FASTA filename;
  each record is listed as `##contig=<ID=...,length=...>`.
- Threshold flags used only by `--stats` / `--aavf`: `--min-freq` (default 0.01),
  `--min-coverage` (default 10), `--sb-alpha` (default 0.05).
- Methods note with citations: [docs/methods.md](docs/methods.md).

### Unchanged
- Default TSV/XML columns, values, and layout when the new flags are omitted.
- No Nextflow content in this repository.

## [1.2.1] - 2026-10-16

### Fixed
- Restored `--protein all` and comma-separated lists (e.g. `PR,RT,INT`) in a **single pass**, matching 1.1.0. Version 1.2.0 treated the whole flag as one protein name and failed with `Reference … header is missing an all protein annotation`.
- Multi-protein TSV again writes one header followed by each protein's rows in requested order.
- Multi-protein XML again wraps each protein's positions in `<Protein name="PR">…</Protein>` (single-protein XML is unchanged, with positions directly under `<SamContainer>`).
- Single-record HIV-1 TSV and XML output is byte-identical to 1.1.0.

### Added
- Regression tests that compare `--protein all` and comma-separated lists against fixtures generated by `codonyat==1.1.0` from PyPI.

## [1.2.0] - 2026-10-13

### Added
- **Multi-record reference FASTA support**: Load references with multiple sequence records (e.g., segmented viruses like Influenza A). Proteins are addressed by (record_id, protein_name) tuple.
- **Multi-interval proteins**: Support for complex protein structures:
  - Programmed ribosomal frameshift (e.g., SARS-CoV-2 ORF1ab with -1 PRF at base 13468, where base 13468 is read twice)
  - Splicing (discontinuous coding sequences)
  - Circular origin-crossing (e.g., HBV polymerase spanning the origin)
- **TSV annotation format**: Optional sidecar annotation file with format `record, protein, description, intervals, strand`
  - Intervals notation: 1-based inclusive coordinates, semicolon-separated for multi-interval proteins
  - Example: `266-13468;13468-21555` for SARS-CoV-2 ORF1ab frameshift
- **RECORD column in output**: For multi-record references, TSV output includes a `RECORD` column after `REFERENCE`
  - Single-record outputs remain byte-identical to v1.1.0 (no RECORD column)
- **Minus-strand gene validation**: Clear error message when minus-strand genes are encountered (not supported)
- **CLI flag**: `--annotation` for specifying TSV annotation files
- **Comprehensive test suite**: 37 tests covering all new features and backward compatibility

### Changed
- `FullReference` class now supports multiple records and optional annotation files
- `Protein` model now uses `Interval` objects and supports multiple intervals per protein
- `calculate_variant_frequencies` method updated to handle multi-interval proteins
- `write_csv` method conditionally includes RECORD column based on number of records

### Fixed
- Import formatting for better code organization
- Validation messages updated for multi-record references

### Backward Compatibility
- Single-record, single-interval workflows remain 100% byte-identical to v1.1.0
- Existing FASTA header annotation format continues to work unchanged
- All existing CLI flags and behavior preserved
- 26 original tests continue to pass unchanged

### Documentation
- Updated README with multi-interval protein examples
- Documented intervals notation: 1-based inclusive, semicolon-separated
- Added TSV annotation format specification
- Clarified RECORD column behavior
- Added "Research use only" wording throughout
